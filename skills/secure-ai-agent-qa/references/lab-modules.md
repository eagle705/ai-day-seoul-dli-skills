# 제공된 실습 PDF로 답하기

수집: 2026-10-29. `DLI_codex`의 한국어 PDF 11개·63페이지를 읽어 페이지별 텍스트와 외부 링크를 코퍼스에 보관했다. PDF 인쇄 머리말은 2026-10-28이다. 이것은 인증된 페이지를 사용자가 내보낸 교재 사본이며 현재 서버의 실행 상태를 확인한 결과가 아니다.

이 자료의 절차는 이전 6-Notebook 가이드보다 우선한다. 모듈 번호는 12-Lesson 강의 체계에 대응한다. 파일은 1~10과 과정 홈뿐이며 **11·12의 상세 모듈 PDF는 없다**. 과정 홈 3~4페이지는 3·4·11을 선택 모듈이며 최종 평가에서 묻지 않는다고 안내한다. 11·12의 구체 절차는 강의 슬라이드·과정 개요에서 확인한 범위로 한정한다.

## 검색

스킬 폴더에서 실행한다. 검색은 Python 표준 라이브러리만 필요하다. 모듈 0은 과정 홈이다.

```sh
python3 scripts/search_labs.py '입력 가드' --module 9 --limit 2 --full
python3 scripts/search_labs.py --module 8 --page 2 --page 3 --full
python3 scripts/search_labs.py --module 0 --page 4 --full --links
```

PDF 페이지 번호는 내부 추적용이다. 기본 답변에는 `근거: 실습 가이드 「모듈 8 · OpenShell 격리」.`처럼 제목을 쓴다. 강의 슬라이드에서 얻은 내용과 섞어 거짓 인용하지 않는다. 그림에만 있는 텍스트·상호작용형 탐색 패널·숨겨진 코드 파일은 텍스트 추출로 확보되지 않았다. “기준 결과 · 완전한 실행” 표기도 학습자의 완료 증거가 아니다.

## 모듈 1~2: 무엇을 만들고 무엇을 공유하는가?

- 노트마다 Title / Summary / Source / Status를 가진 항목을 `workspace-map.md`에 만든다. 검토 전 상태는 `unreviewed`다. 강의의 예전 “인덱스”와 노트 워커의 별도 인덱스를 혼동하지 않는다.
- 새 세션의 대화 기억과 파일 접근은 별개다. 대화를 모르는 검토자도 같은 파일과 실습 연결을 공유하면 대상을 수정할 권한이 있을 수 있다.
- 모듈 2의 서비스는 읽기 전용 목록과 노트를 제공한다. PDF의 예시 주소는 `127.0.0.1:8765`, 목록은 `/index`다. 실제 생성 코드와 기록을 보지 않고 이 포트나 모든 라우트를 확정하지 않는다. 강의의 다른 포트 예시를 섞지 않는다.
- 모듈 2는 시간 제한을 둔 서비스를 만들고 다른 job에서 두 읽기를 확인한 뒤 **서비스를 중지**하도록 한다. 셸 경로, 패키지 설치, 외부 공개를 하지 말라는 실습 제한이 있다. “완료하려면 계속 실행해야 한다”고 답하지 않는다.
- 증거는 목표별로 실제 일어난 일을 그린 파일을 등록하는 실습 기능이다. PDF의 `확인 … 0개 완료`는 저장 당시 UI 상태일 뿐 학생의 현재 진행률이 아니다.

## 모듈 3~4: 결과를 어떻게 명명하는가?

- 정찰의 주장은 **관찰됨 / 소스로 뒷받침됨 / 아직 알 수 없음**으로 나눈다. 카나리는 연습 디렉터리 안의 무해한 파일로 한정한다.
- 노트 인젝션이 거부됐어도 같은 계정의 직접 쓰기가 가능할 수 있다. 직접 쓰기를 **인젝션 성공**으로 세지 않는다. 기준 실행에서 모델이 저항했다는 서술도 모든 모델의 결과가 아니다.
- 모듈 4는 합성 키만 사용한다. 변경하고 다시 인증 코드를 만들지 않은 요청의 거부, 정상 인증 코드가 붙은 불필요한 쓰기의 수락을 비교한다. 정상 인증은 목적이나 인가를 입증하지 않는다.
- 읽기 전용 키는 수신기 경로의 쓰기를 막으며, 동일 계정의 디스크 직접 쓰기는 별도 경로다. 키 파일 위치·읽을 수 있는 주체만 조사하고 키 값·환경변수는 출력하지 않는다.
- 의존성 고정으로 연결 하나를 끊은 뒤 유용한 읽기가 유지되는지도 확인한다. PDF는 이전 합성 키 정리를 요구하지만 Q&A 요청만으로 파일을 삭제하지 않는다.

## 모듈 5~7: 공격을 어떻게 해석하는가?

- 모듈 5~7의 공통 대상은 `reviewed/notes-worker/` 키트의 노트 워커다. 이 키트의 실제 파일은 PDF에 포함되지 않았으므로 정확한 전체 코드나 숨겨진 페이로드를 재구성했다고 주장하지 않는다.
- 한 번에 입력 하나를 바꾸고 깨끗한 대조군과 비교한다. 공격이 안 되면 심은 문장·워커 사본·전달한 실제 작업을 먼저 확인한다. PDF의 제한은 새 세션에서 두 번 거부하면 **저항됨**으로 기록하는 것이다. 성공할 때까지 무제한으로 재시도하도록 안내하지 않는다.
- 출력함은 실습 안의 반출 목적지 모형이다. 모듈 5는 출력함의 어떤 내용도 실습 환경을 떠나지 않는다고 명시한다. 카나리가 출력함에 나타난 것과 인터넷으로 실제 전송된 것을 구분한다.
- 출력함을 없앤 뒤에도 카나리가 인덱스 등 다른 곳에 남는지 확인한다. 경로 하나 제거를 모든 유출 경로의 차단으로 일반화하지 않는다.
- 모듈 6의 보호 규칙은 PDF 1페이지의 절차·정확성·개인정보·비밀 유지다. 리뷰어라는 말만 믿는지 시험하며, 규칙의 요약 유출은 카나리 문자열 검색만으로 판정할 수 없다.
- 모듈 7은 필요 없는 `publish()`, 저장 절차, 자가 복사 인계 문서, 실행 의존성을 구분한다. 모델을 설득하는 텍스트와 프로세스 권한으로 실행되는 코드를 같은 메커니즘으로 설명하지 않는다.

## 모듈 8: OpenShell v0.1.2의 실제 실습 범위

- PDF는 **v0.1.2**를 명시한다. Codex는 자체 컨테이너에서 밖에 있고 job은 OpenShell 게스트 안에 있다. 이는 자료가 설명하는 배치이며 현재 서버 프로세스를 확인한 결과는 아니다.
- 파일 규칙은 생성 시 고정되고 바꾸려면 재생성이 필요하다. 네트워크 규칙은 실행 중 변경 가능하며 사용자가 스튜디오 **권한 탭**에서 적용한다. 과거 장표의 “Evidence 탭에서 적용” 표현보다 현재 제공된 실습 본문을 우선한다.
- 훈련용 규칙에는 프로그램·호스트·포트·HTTP 메서드·경로와 `enforcement: enforce`가 필요하다. PDF는 v0.1.2에서 이 설정이 없으면 금지된 HTTP 요청을 기록만 하고 통과시킨다고 설명한다.
- 예시 기준선은 게스트 `/usr/bin/curl` → `docs.openclaw.ai`의 `/start/getting-started`, `/concepts/memory` 두 페이지다. 둘 다 200인지 확인한 뒤 memory만 제외하고 같은 클라이언트로 다시 비교한다. 예시의 200→403은 문서에 적힌 결과다.
- 명시적 OpenShell 거부와 규칙을 보이는 403, 커널의 EACCES, 원격 문서 사이트의 404, DNS·시간초과를 구분한다. 일반적으로 403 하나만으로 발급 주체를 알 수 없으므로 응답과 로그를 확인한다.
- 네트워크 규칙은 허용된 연습 폴더의 로컬 표시 파일 쓰기를 막지 않는다. 최종 지도에 통제·소유자·근거·미시험 항목을 기록한다.

## 모듈 9~10: 탐지·역추적·강제의 차이

- 입력 가드는 6개 단어 패턴을 표시하는 스크립트이며 파일을 수정하지 않는다. 탐지된 줄이 곧 차단된 실행을 뜻하지 않는다. 바꿔 쓴 승인 표현이 탐지되지 않았는지와 실제 Status 변화를 따로 본다.
- 출력 가드는 검토 기록이 없는 상태 변경과 비공개 문장을 되풀이한 출력함을 찾는다. 결과 → 쓴 job → 입력으로 추적한다. 파일의 모양만 검사하는 것과 원인 규명은 다르다.
- 출처 레이블과 `yes` 대기 단계는 이 실습에서 **워커 절차의 텍스트**다. 모델 외부의 강제 테인트 추적·승인 게이트가 구현됐다고 답하지 않는다.
- 모듈 10의 Reader/Publisher는 역할을 나누지만 같은 계정을 쓴다. Reader의 직접 출력함 쓰기가 거부되는지도 따로 시험한다.
- 목록 밖 호스트에 대한 모듈 10의 기준 요청은 연결 단계에서 실패했으며 모듈 8의 명시적 403이 없었다. 실패의 출처를 확인해야 한다. 파일 쓰기 허용과 외부 이그레스 거부도 별개다.
- 정책 전체에서 정한 속성을 검사하는 짧은 스크립트와 OpenShell SMT 증명기를 동일시하지 않는다. 한 속성·정책 모델·규칙 범위의 검사는 모든 배포 효과의 증명이 아니다.
- 엄격한 규칙을 추가하는 실습은 모델 재학습이 아니다. 정상 인덱스에도 Status가 필요하므로 공격 거부와 정상 작업 손실을 함께 평가한다.
