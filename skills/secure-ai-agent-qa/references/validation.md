# 대표 질문으로 검증하기

구조 검사: `python3 <skill-creator의 경로>/scripts/quick_validate.py <이 스킬 폴더>`.

아래는 스킬을 갱신할 때 답변 품질을 점검하기 위한 질문과 평가 기준이다. 질문의 문구를 그대로 외우게 하지 말고 실제 인용 근거를 확인한다. 원격 실행과 평가 제출은 필요하지 않다.

코퍼스 갱신 예시:

```sh
python3 scripts/build_slide_corpus.py --seoul /path/to/DLI_AI_Day_Seoul-Develop-Secure-AI-Agent.pptx --berlin /path/to/DLI_GTC_Berlin-Develop-Secure-AI-Agent.pptx
python3 scripts/search_sources.py --deck seoul --slide 82 --slide 115 --full
python3 scripts/search_sources.py 'lethal trifecta' --deck berlin --limit 2 --full
```

장표가 추가되거나 이동했으면 topic-map·Q&A 가이드·그림의 인용 번호도 함께 갱신한다. 파일 이름만 동일한 새 PPTX를 기존 내용으로 간주하지 말고 sources.json의 SHA-256을 비교한다.

## 2026-10-28 생성 시 확인한 항목

- 두 PPTX의 실제 발표 순서와 추출 순서 일치: 서울 143장 / 노트 134장, 베를린 129장 / 노트 120장.
- 한국어·영어 검색어 6종을 양쪽 덱에서 검색하고 관련 장표가 반환되는지 확인.
- 정확한 슬라이드 선택 시 전체 본문·노트가 반환되고, 범위 밖 번호는 오류로 처리됨을 확인.
- Markdown 상대 참조 경로와 skill-creator 구조 검사 통과.
- 실습 URL 두 개는 인증 요구 상태를 확인했으며 본문 수집·실습 실행·평가 제출은 수행하지 않음.

위 확인은 코퍼스와 도구에 대한 검사다. 실제 Q&A 모델의 독립 평가를 수행한 기록은 아니다.

## 근거 표기 확인

일반 Q&A 답변은 `근거: 강의 슬라이드 「주제」.`로 표기한다. 개최지·덱 이름·자료별 번호를 그대로 노출하지 않는다. 예를 들어 OWASP 질문은 `근거: 강의 슬라이드 「OWASP GenAI/LLM Top 10 2026」.`로 표기한다. 내부 출처 ID와 번호는 추적을 위해 유지한다.

갱신 명령은 `python3 scripts/build_lab_corpus.py --input /path/to/DLI_codex`이다. 갱신에만 PyMuPDF가 필요하다. 검색은 표준 라이브러리만 쓴다. 원 PDF의 SHA-256·페이지 수, 정확한 모듈/페이지 조회, 없는 모듈 오류, 모든 로컬 참조 링크를 확인한다. 모듈 11·12가 추가되면 갱신 스크립트의 제목 매핑과 출처 범위도 수정한다.

## 2026-10-29 갱신 시 실행한 검사

- 스킬 구조 검사 및 Markdown 로컬 참조 경로 검사 통과.
- 원 PDF 11개의 SHA-256과 페이지별 레코드 수 일치, 총 63페이지·모듈 0~10 확인.
- 외부 읽을거리 URL 46개의 인용 위치와 신규 원 자료 검토 17개의 참조 경로 확인.
- 모듈 8의 정확한 페이지 조회에서 v0.1.2와 enforcement: enforce 본문 확인.
- 모듈 9 검색과 홈 더 읽을거리 조회 통과. 없는 모듈 11·12, 범위 밖 페이지, 모듈 없는 페이지 요청은 명시적 오류로 처리됨을 확인.
- 기존 강의 코퍼스 272장 보존 확인.
- PDF의 구성도와 정책·검색 공격·속성 검사 관련 페이지 4개를 렌더링해 텍스트의 관계를 시각적으로 확인. 이미지 전용 원문 전체에 대한 OCR은 수행하지 않음.
- 원격 실습·평가 제출·논문 실험 재현·독립 모델 Q&A 평가는 수행하지 않음.
